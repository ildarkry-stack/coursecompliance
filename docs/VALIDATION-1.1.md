# Проверка выпуска 1.1.0-rc1

Этот выпуск содержит исправления по результатам анализа 1.0.0. Код изменён и упакован для обновления Moodle, однако PHP и Moodle в среде подготовки отсутствуют. Выпуск имеет статус RC, а не stable. Установку сначала следует проверить на тестовой копии Moodle 5.1.1.

## Реализовано

- Сохранение снимка конфигурации профиля и SHA-256 при постановке аудита в очередь. Пакеты и AutoFix используют эти правила; повторная проверка после AutoFix наследует тот же снимок. Старые аудиты без снимка явно обозначаются в отчёте.
- Индикатор курса исключает дочерние пакеты. Action Center и отчёт банка используют общий SQL-критерий опубликованного актуального результата; отключённые профили исключаются из текущих сводок.
- Обычные страницы основного отчёта используют LIMIT/OFFSET через Moodle DML. Сводка читается recordset, хранится не более пяти примеров курсов на группу отсутствующих элементов.
- Сложные фильтры missing/mismatch/autofix сохраняют точную прежнюю PHP-семантику и обрабатывают recordset, удерживая только страницу. Их полный проход по выборке сохраняется; это ещё не SQL-фильтрация всех вычисляемых признаков.
- «Готовые курсы» ограничены курсами, реально присутствующими в снимке выбранного аудита.
- Банк вопросов: SQL-фильтры до пагинации, полный COUNT и SQL-агрегаты. Ранее интерфейс ограничивался первыми 10 000 результатами. Подсчёт подробностей вопросных нарушений также выполняется группировкой в БД.
- Финализатор использует INSERT SELECT вместо INSERT для каждой строки. Публикация родителя и удаление дочерних данных выполняются в одной транзакции. Повтор завершённого финализатора не копирует результаты заново.
- Отдельные метрики финализации; показатели worker накапливают затраты неудачных попыток. Peak memory подписан как пик PHP-процесса, а не память отдельного пакета. Финализационные метрики снимаются перед финальным UPDATE родителя и COMMIT и не включают их стоимость или доставку уведомления.
- Постановка дерева задач выполняется транзакционно и под Moodle Lock API. Повторная постановка уже существующего дерева не дублирует пакеты. Retry и финализация используют один родительский lock; worker — собственный lock. Неполное дерево получает явную ошибку вместо бесконечного ожидания отсутствующих пакетов.
- Массовые изменения обрабатывают только pending-записи. Успешное изменение и статус applied фиксируются вместе. Продолжения выполняются по 100 активностей в отдельной AdHoc-задаче. Прогресс учитывает уже сохранённые applied/skipped/failed.
- Очистка работает порциями до 100 завершённых аудитов и 100 завершённых/частичных операций. Running, queued, failed и данные незавершённого восстановления не удаляются по возрасту.
- Чтение метаданных и содержимого банка ограничено 5 000 записей на тест; глубокая проверка — 500 вопросами. При превышении показывается существующее нарушение уровня notice «проверка частичная». Кэш ответов сбрасывается между тестами. Полная загрузка объектов вопросов через Quiz API пропускается при более чем 500 слотах.

## Важные оставшиеся ограничения

Получение кандидатов случайных вопросов через Moodle random_question_loader по-прежнему может вернуть большой набор. Поэтому нельзя считать всю проверку банка ограниченной 5 000 строками по памяти. Суммы категорий/дубликатов/неиспользованных вопросов при частичной проверке относятся к проверенной части; точный размер полученного пула сохраняется. Строгий бюджет памяти всей проверки потребует отдельного совместимого с Moodle API решения.

Вычисляемые представления Action Center «новые» и AutoFix, а также delta/composite-отчёты ещё используют существующие помощники с загрузкой истории. Обычная SQL-пагинация не означает, что все страницы плагина уже оптимизированы. Для основного отчёта число групп отсутствующих элементов влияет на память сводки.

Автоматическая отмена, heartbeat/watchdog, восстановление потерянных задач, инкрементальные проверки, расписание аудита, ответственные за нарушения и XLSX-экспорт в этот выпуск не включены. Нет автоматического признания долго выполняющегося worker умершим: это могло бы дублировать действующую задачу. Используйте диагностику Moodle и плагина.

Провалившиеся операции и аудиты сохраняются для восстановления и не очищаются автоматически по сроку. Это может увеличивать историю; нужна отдельная политика удаления таких данных. Исходящие уведомления остаются best effort: сбой после commit публикации может помешать отправке без потери самого результата.

## Локально выполнено

Запущен `docs/validation/static_release_check.py`:

- XML разобран; id, поля ключей/индексов и внутренние ссылки согласованы.
- Четыре новых поля install.xml сопоставлены с новым идемпотентным upgrade step.
- EN/RU: одинаковые ключи, без дубликатов, с алфавитным порядком.
- Выполнена простая лексическая проверка баланса разделителей PHP. Она не заменяет PHP lint.
- На SQLite выполнены SQL-регрессии индикатора, фильтрации банка до пагинации, агрегатов, чистой повторной проверки, отключённого профиля, ограничения «готовых курсов» и групповой финализации.
- Проверены корень и содержимое итогового ZIP, CRC и версия.

Машиночитаемые результаты находятся в `docs/validation/local-results.json`. SQLite используется только как локальный SQL-эксперимент, не как поддерживаемая СУБД Moodle.

## Добавленные тесты Moodle

`tests/release_regression_test.php` содержит сценарии:

1. Снимок профиля не меняется после редактирования стандарта; повтор scheduler не создаёт дубликаты.
2. Завершённый дочерний пакет не подменяет опубликованный индикатор.
3. Страницы отчёта не пересекаются, количество полное, семантические фильтры сохранены.
4. Поиск в банке находит вопрос за пределами первой страницы; чистый recheck скрывает старые детали.
5. Продолжение массового изменения сохраняет applied и не превращает их в skipped.
6. Очистка сохраняет running и failed.
7. Групповая финализация сохраняет детали, удаляет детей и не дублируется при повторе.

Также обновлены проверка релиза в diagnostics_test и проверка новых полей схемы. Эти PHPUnit-тесты подготовлены, но не запускались в среде подготовки.

## Обязательный внешний gate

На тестовой копии: PHP lint, moodle-plugin-ci PHPCS/PHPDoc/validate/savepoints, clean install и PHPUnit. Затем upgrade с 1.0.0 с сохранением данных. Матрица должна включать заявленные Moodle 5.0/5.1/5.2 и PostgreSQL/MySQL. Перед stable нужны журналы успешных запусков.

Для производительности повторить ступени 50/100/250/500/1 000 курсов, большие общие банки, несколько десятков исторических аудитов, разные размеры пакетов и 1/2/4 реально работающих cron worker. Измерять PHP RSS/peak, SQL, календарное время, финализацию, HTTP и дисковый объём. Новые численные показатели скорости PHP/Moodle для этого выпуска не заявляются.

Проверить прерывание worker/finalizer, транзакционный rollback при ошибке копирования, конкурирующие retry, сбой публикации задач, повтор activity continuation и откат применённых изменений. Для исторических записей без configsnapshot проверить сообщение о fallback.
